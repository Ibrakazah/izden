# Бриф генератора юнитов «Ізден» (вход для ИИ-генератора)

Ты пишешь учебные юниты по читательской грамотности в формате PISA для учеников 7–9 классов Казахстана.
Юнит = короткий текст (сплошной или несплошной) + 3–5 вопросов с выбором ответа. Каждый неверный вариант —
это типичная ловушка, у неё есть тип и объяснение. Ученик читает с телефона, поэтому текст короткий:
**120–260 слов** (таблица — до 8 строк данных и до 5 колонок).

## Схема JSON (строго)
Файл: `{"units":[ ...юниты... ]}`. Юнит:
```json
{"id":"ru-bus-01","grade":8,"title":"Расписание автобуса","format":"table","context":"rural",
 "blocks":[
   {"id":"b1","type":"p","text":"Предложение один. Предложение два."},
   {"id":"b2","type":"table","caption":"Подпись","rows":[["Заголовок 1","Заголовок 2"],["ячейка","ячейка"]]},
   {"id":"b3","type":"list","items":["пункт 1","пункт 2"]},
   {"id":"b4","type":"chart","caption":"Осадки по дням","unit":"мм","rows":[["Пн",4],["Вт",0]]},
   {"id":"b5","type":"h","text":"Подзаголовок"}],
 "questions":[{"id":"q1","process":"locate","difficulty":1,
   "stem":"Вопрос?",
   "options":[{"id":"a","text":"…","correct":true},
              {"id":"b","text":"…","correct":false,"trap":"misread_table","why":"…"}],
   "evidence":["b2:r3"],
   "hint_steps":["Шаг 1 …","Шаг 2 …"],
   "explain":"Почему верный ответ верный, со ссылкой на текст."}]}
```
- `format`: `table` | `continuous` | `notice` (объявление, памятка, реклама, афиша) | `chart` (столбчатая диаграмма) | `mixed` (текст + таблица/список).
- `context`: `rural` (аул, село, ферма, сельская школа, райцентр, акимат сельского округа) | `urban` | `everyday`.
- `process`: `locate` (найти информацию) | `understand` (понять, вывести, связать части) | `evaluate` (оценить надёжность, цель автора, качество аргумента, применить к своей ситуации).
- `difficulty`: 1 (прямо написано), 2 (нужно связать 2 места или сделать простой вывод), 3 (вывод из нескольких мест / оценка).
- `options`: 3 или 4 варианта, **ровно один** `"correct": true`. У каждого неверного: `trap` и `why` (1–2 предложения, обращение к ученику на «ты», объясняет, почему вариант привлекателен и где ошибка).
- `trap` (только эти значения):
  - `word_match` — вариант повторяет слова из текста, но не отвечает на вопрос;
  - `near_detail` — соседняя деталь (соседняя строка, другой день, другой человек);
  - `outside_knowledge` — правдоподобно по жизни, но в тексте этого нет;
  - `overgeneralize` — слишком общий или слишком сильный вывод («всегда», «все»);
  - `opposite` — перепутан смысл, причина и следствие, «да» и «нет»;
  - `misread_table` — не та строка или колонка таблицы/диаграммы (например, отправление вместо прибытия).
- `evidence`: где в тексте доказательство. Формат: `b3` (весь блок), `b3:s2` (2-е предложение абзаца), `b2:r3` (3-я строка данных таблицы; заголовок — r0, его не указывай), `b4:r2` (2-й столбик диаграммы), `b5:i1` (1-й пункт списка). Нумерация с 1. Указывай самое точное место (предложение/строку), не весь блок, если можно.
- **Разбиение на предложения делает программа** по правилу: после `.`, `!`, `?` или `…` и пробела начинается новое предложение. Поэтому НЕ используй сокращения с точкой внутри предложения («т. е.», «г.», «руб.», «т.б.», «т.с.с.», «ж.»), пиши «2025 год», «тенге», время как `15:00`, дроби через запятую `2,5`.
- `hint_steps`: 2–3 шага, которые ведут к ответу, но не называют его («Найди в таблице колонку „Прибытие“», «Сравни время с 15:00»).
- `explain`: 1–2 предложения: почему верный ответ верный.
- id вопросов внутри юнита: q1, q2, …; id блоков: b1, b2, …; id вариантов: a, b, c, d. Верный вариант ставь на разные позиции (не всегда «a»).

## Требования к качеству (самое важное)
1. **Однозначность.** На каждый вопрос есть ровно один ответ, который можно доказать текстом. Неверные варианты точно неверны по тексту (не «спорно»). Для `evaluate` верный ответ — тот, который лучше всего опирается на текст; неверные — явно слабее с понятной причиной.
2. **Ответ требует текста.** Вопрос нельзя решить общими знаниями без чтения.
3. **Ловушки живые:** это реальные ошибки подростков (не абсурдные варианты). Длина вариантов примерно одинаковая; верный не должен быть самым длинным.
4. **Цифры в тексте согласованы** (суммы, время в пути, даты, дни недели). Перепроверь арифметику.
5. Казахстанская жизнь: тенге, аким, акимат, райцентр, аул/село, eGov, ЕНТ, Наурыз, кошары, зимовка скота, сенокос, сельская амбулатория, школьный автобус. Имена казахстанские (Айгерим, Нурлан, Дана, Ерлан, Асель, Тимур, Мадина, Олжас и т. п.). Организации и цифры — вымышленные, но правдоподобные; не выдавай их за реальную статистику, не упоминай реальные бренды лекарств.
6. Уровень: 7 класс — проще и короче, 9 класс — длиннее, с аргументами и несколькими источниками.
7. Для `evaluate`: цель автора, надёжность источника (реклама vs факты), сильнее/слабее аргумент, что ещё нужно проверить, применить правило к ситуации.
8. Тон уважительный, без морализаторства. Безопасность: медицинские/ветеринарные тексты не дают опасных советов (всегда «по назначению врача/ветврача»).

## Язык
- Казахские юниты пишутся **сразу на казахском** (не перевод с русского): простой грамотный литературный язык, правильные буквы ә, ғ, қ, ң, ө, ұ, ү, һ, і; без кальки с русского. Ловушки, why, hints, explain — тоже на казахском, обращение «сен».
- Русские юниты — на русском, обращение «ты».

## Самопроверка (обязательно)
Сохрани файл и запусти:
```
python3 scripts/check.py <твой файл>
python3 scripts/check.py --show <твой файл>
```
Первая команда должна дать 0 ошибок. Вторая печатает текст с номерами предложений и строк — сверь, что каждое evidence указывает на нужное место.
Затем реши каждый свой вопрос заново, глядя только на `--show`, и исправь всё, что неоднозначно.

## Уроки раунда 1 (добавлено после проверки 24 юнитов)
Частые замечания проверяющих — не повторяй их:
- **Верный вариант самый длинный** — частая подсказка. Делай варианты одной длины (±20%).
- **Тип ловушки не соответствует сути** варианта — выбирай trap по тому, КАК ученик ошибается.
- **why с родом** («ты взяла»/«ты взял») — пиши нейтрально: «Это время отправления, а нужно время прибытия».
- **Правило в тексте допускает два прочтения** (например, «3 сухих дня» — входит ли день покоса). Формулируй правила так, чтобы их нельзя было понять двумя способами.
- **Условие вопроса неполное** (ключ верен только при допущении, которого нет в тексте/вопросе) — добавь недостающее условие в stem.
- **Текст короче 120 слов** — для 8–9 классов держи 150–260 слов (вместе с таблицей).
- **Казахский:** «теңге» (не «тенге»), «жадынама», без калек («жұмыс істеймін 18 жыл» → «18 жылдан бері жұмыс істеймін»), без плеоназмов «әр … сайын».
- Телефоны не выдумывай похожими на реальные: только 112 или «байланыс орталығы». Названия лекарств — явно вымышленные.
