# Формат заданий по математике для Ізден

Ізден — тренажёр для 7–9 классов сельских школ Казахстана. Правило продукта: ученик сначала нажимает в условии
строку или предложение, где лежат нужные данные («доказательство»), и только потом выбирает ответ.
Задания по математике — это математическая грамотность в духе PISA: жизненная ситуация, таблица или текст, расчёт.
Тексты заданий PISA/OECD копировать нельзя — придумывай свои ситуации.

## Что написать
Один файл на язык: `{"units":[ ...5 units... ]}`. Русский и казахский файлы — параллельные: те же id блоков, вопросов и
вариантов, те же числа, те же `correct`, `trap`, `evidence`, `process`, `difficulty`. Отличаются только тексты и префикс id.

## Unit
```json
{
 "id": "ru-m-pct-01",            // <lang>-m-<topic>-<NN>; в казахском файле kk-m-pct-01
 "subject": "math",
 "topic": "percent",             // percent | money | ratio | data | geometry
 "grade": 8,                     // 7, 8 или 9
 "title": "Скидка в магазине",
 "format": "table",              // table | continuous | notice | chart | mixed
 "context": "rural",             // rural | urban | everyday  (в основном rural)
 "blocks": [ ... ],
 "questions": [ ...ровно 3... ]
}
```

## Блоки (условие задачи)
- `{"id":"b1","type":"p","text":"..."}` — абзац. Предложения делятся по `. ! ? …` + пробел и нумеруются с 1: `b1:s2`.
  ВАЖНО: не ставь точку с пробелом внутри предложения («т. е.», «1. шаг», «5 тыс. тенге») — это сломает нумерацию.
  Десятичные пиши через запятую без пробела: `2,5`.
- `{"id":"b2","type":"table","caption":"...","rows":[["Заголовок1","Заголовок2"],["..",".."]]}` — rows[0] заголовок,
  строки данных нумеруются с 1: `b2:r1` — первая строка данных. Все строки одной длины. Ячейки — строки или числа.
- `{"id":"b3","type":"chart","caption":"...","unit":"кг","rows":[["Пн",12],["Вт",15]]}` — столбчатая диаграмма,
  значение — число. `b3:r1` — первая строка.
- `{"id":"b4","type":"list","items":["...","..."]}` — список, `b4:i1`.
- `{"id":"b5","type":"h","text":"..."}` — подзаголовок (на него нельзя ссылаться в evidence).
В каждом unit 2–4 блока, обязательно хотя бы один `p`. Условие короткое: 40–110 слов плюс таблица/диаграмма.
В условии должны быть лишние данные (отвлекающие числа), чтобы выбор нужной строки был содержательным.

## Вопрос
```json
{
 "id": "q1",
 "process": "locate",        // q1 = locate, q2 = understand, q3 = evaluate (строго в этом порядке)
 "difficulty": 1,            // 1, 2 или 3; q1 обычно 1–2, q2 — 2, q3 — 2–3
 "stem": "Сколько стоит ...?",
 "options": [
   {"id":"a","text":"1200 тенге","correct":true},
   {"id":"b","text":"1600 тенге","correct":false,"trap":"near_detail","why":"Сложены полные цены, скидка не учтена."},
   {"id":"c","text":"600 тенге","correct":false,"trap":"misread_table","why":"..."},
   {"id":"d","text":"1400 тенге","correct":false,"trap":"overgeneralize","why":"..."}
 ],
 "evidence": ["b2:r2","b1:s3"],
 "hint_steps": ["Шаг 1 ...","Шаг 2 ...","Шаг 3 ..."],
 "explain": "800 − 200 = 600 тенге за поездку, 600 × 2 = 1200 тенге."
}
```
- `process`: **locate** — найти и взять из условия нужное число (или одно простое действие с ним);
  **understand** — расчёт в 2–3 действия; **evaluate** — оценить утверждение или выбор («Прав ли Асхат?», «Что выгоднее?»,
  «Хватит ли?») — ответ с обоснованием.
- Ровно 4 варианта, ровно один `correct:true`. Позицию верного варианта меняй (не всегда `a`).
- Каждый неверный вариант — результат КОНКРЕТНОЙ типичной ошибки, а не случайное число. `why` объясняет эту ошибку
  по-доброму, НЕ называя верный ответ. `trap` — один из:
  - `misread_table` — взял не ту строку/колонку/единицу измерения;
  - `near_detail` — взял соседнее число или пропустил условие (скидку, «на каждого», «туда и обратно»);
  - `overgeneralize` — сделал лишь часть расчёта или распространил частный случай на всё;
  - `opposite` — перепутал направление (больше/меньше, прибавил вместо вычесть, обратная пропорция);
  - `word_match` — сработал на знакомое слово/число из вопроса, не вникая;
  - `outside_knowledge` — ответил «из жизни», а не по данным условия.
- `evidence` — ВСЕ строки/предложения, в которых лежат данные, нужные для ответа (1–3 ссылки). Ученику засчитывается
  нажатие на любую из них. Ссылки обязаны существовать (проверит скрипт).
- `hint_steps` — 2–3 шага, которые ведут к решению, но НЕ содержат готового ответа и итоговых чисел.
- `explain` — полное решение с действиями и числами.
- Варианты примерно одной длины; верный не должен быть самым длинным или самым подробным.

## Качество математики (самое важное)
- Пересчитай КАЖДЫЙ ответ дважды. Ответ однозначный, один верный вариант, остальные точно неверны.
- Числа «школьные»: ответы целые или с одной-двумя цифрами после запятой. Цены в тенге правдоподобные для Казахстана
  (хлеб ~200, бензин ~250 за литр, билет на автобус 500–1500).
- Имена казахстанские (Айгерим, Нурлан, Дана, Асхат, Мадина, Ерлан, Жансая, Олжас), сёла вымышленные.

## Казахский файл
Естественный литературный казахский, не калька. Числа и структура те же. «тенге» = «теңге», «процент» = «пайыз».
То же правило про точку с пробелом внутри предложения.

## Проверка (обязательно)
Из корня проекта: `python3 scripts/check.py data/staging_math/<файл>.json` — должно быть `0 errors` для обоих файлов.
Посмотреть нумерацию предложений и строк: `python3 scripts/check.py --show data/staging_math/<файл>.json`.
